## 2026-10-02 - Resolve N+1 correlated subqueries on paginated base queries
**Learning:** Using `SELECT` correlated subqueries directly in the `SELECT` clause for multiple aggregates (like `AVG(score)` and `COUNT(*)`) causes redundant index lookups per row. Applying `LATERAL` joins directly in the main `FROM` clause before a `LIMIT` causes Postgres to evaluate the join for every matched row before sorting, leading to massive performance regressions.
**Action:** When refactoring Postgres correlated subqueries in `SELECT` clauses into `LEFT JOIN LATERAL`, consolidate multiple aggregates querying the same target table into a single `LATERAL` subquery. On paginated endpoints, isolate the base query (with `WHERE`, `ORDER BY`, and `LIMIT` clauses) into a subquery first, and then apply the `LATERAL` joins to those paginated results.
