## 2026-09-29 - Optimize PostgreSQL N+1 correlated subqueries with LATERAL joins
**Learning:** Correlated subqueries in the SELECT clause evaluate on every returned row and execute N+1 times, leading to database performance regressions. When optimizing them into LEFT JOIN LATERAL, applying the lateral join directly in the main FROM clause before a LIMIT forces Postgres to evaluate the join for all matched rows before sorting and limiting. We can additionally consolidate multiple aggregates querying the same table (e.g., AVG(score) and COUNT(*)) into a single LATERAL subquery.
**Action:** Isolate the base query (with WHERE, ORDER BY, and LIMIT clauses) into a subquery first, and then apply the LATERAL joins to those paginated results. Combine multiple aggregates hitting the same table to prevent redundant lookups.
