## 2024-03-01 - N+1 Query Fix with LATERAL JOINS
**Learning:** In PostgreSQL, correlated subqueries within a SELECT clause (like `(SELECT AVG(score) FROM ratings WHERE song_id = s.id)`) are executed row-by-row, leading to an N+1 performance issue. Replacing these with `LEFT JOIN LATERAL` allows PostgreSQL to optimize the query plan, potentially using nested loops or hash joins more efficiently, especially when multiple aggregates are fetched from the same table.
**Action:** When fetching aggregated data (like ratings, counts) alongside main table rows, prefer using `LEFT JOIN LATERAL` over inline correlated subqueries to avoid N+1 lookups per row, resulting in significant performance improvements. Note that `LATERAL` joins should be avoided if the aggregate is used in an `ORDER BY` with a `LIMIT`, as it could cause nested loop performance regressions by preventing early limits.
