## 2024-05-23 - LATERAL Joins on Paginated Endpoints
**Learning:** Replacing correlated subqueries in SELECT with LEFT JOIN LATERAL on paginated endpoints requires isolating the base query (WHERE, ORDER BY, LIMIT) into a derived table first. If LATERAL joins are applied directly in the main query block before limiting, PostgreSQL will evaluate the lateral joins for every matched row prior to sorting, causing massive N+1 performance regressions on large result sets. Consolidating multiple aggregates into a single LATERAL query also reduces redundant index lookups.
**Action:** When optimizing N+1 queries using LATERAL joins with pagination, push the pagination (LIMIT/OFFSET) and sorting down into a base subquery before applying the LATERAL joins, provided the ORDER BY does not depend on the aggregates.
