## 2024-03-20 - Refactoring Correlated Subqueries
**Learning:** Refactoring correlated subqueries in SELECT clauses (e.g., `(SELECT COUNT(*) FROM table WHERE id = main.id)`) into `LEFT JOIN LATERAL` can yield significant performance improvements by preventing redundant index lookups per row. Crucially, when applying `LATERAL` joins on paginated endpoints, the base query (with `WHERE`, `ORDER BY`, and `LIMIT` clauses) must be isolated into a subquery *first*. Applying `LATERAL` joins directly in the main `FROM` clause before a `LIMIT` causes Postgres to evaluate the join for every matched row before sorting, leading to massive performance regressions.
**Action:** Always isolate the paginated base query before applying `LEFT JOIN LATERAL` for aggregates. Consolidate multiple aggregates querying the same target table into a single `LATERAL` subquery.
