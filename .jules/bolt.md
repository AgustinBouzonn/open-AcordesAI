## 2025-02-28 - Avoid Object.fromEntries for Object Filtering in Performance-Critical Paths
**Learning:** Using `Object.fromEntries(Object.entries({...}).filter(...))` to filter out `undefined` properties creates significant allocation overhead due to the intermediate object creation, `Object.entries` generating an array of key-value pair arrays, and then `.filter` generating another array before reconstructing the object.
**Action:** In performance-critical paths like data serializers (e.g., `backend/src/serializers/song.ts`), replace this pattern with manual object construction and conditional property assignments (e.g., `if (val !== undefined) obj.key = val`) to eliminate the overhead. Always ensure all properties—including base ones—are checked conditionally to avoid inadvertently including `undefined` keys.
