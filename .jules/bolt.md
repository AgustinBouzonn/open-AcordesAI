## 2025-03-03 - Optimize PostgreSQL Subqueries with LATERAL Joins
**Learning:** Using standard LEFT JOIN on fully aggregated subqueries (e.g., SELECT ... GROUP BY) causes PostgreSQL to perform a full table scan before joining, regardless of the outer query's filters. Inline correlated subqueries in the SELECT clause (e.g., SELECT (SELECT COUNT(*)...), (SELECT AVG(score)...)) execute separately for every row and column, compounding execution time.
**Action:** Replace full aggregation subqueries and multiple inline correlated subqueries with LEFT JOIN LATERAL (...) ON true. LATERAL allows the subquery to reference columns from preceding tables, enabling PostgreSQL to push down filters and use indexes effectively for the specific rows being queried, reducing both I/O and query latency.
