## 2023-10-24 - Resolving N+1 Correlated Subqueries
**Learning:** Using inline, scalar, correlated subqueries within a SELECT clause combined with early LIMIT/OFFSET and sorting forces Postgres to evaluate the subqueries for every candidate row before sorting, ignoring table indexes and resulting in massive performance regressions, especially for paginated endpoints like songs search.
**Action:** When refactoring Postgres correlated subqueries in SELECT clauses into LEFT JOIN LATERAL on paginated endpoints, isolate the base query (with WHERE, ORDER BY, and LIMIT clauses) into a subquery first, and then apply the LATERAL joins to those paginated results. Consolidate multiple aggregates querying the same target table (e.g., AVG(score) and COUNT(*)) into a single LATERAL subquery.
